# 논담 홈페이지 관리자 운영

## 시작하기

Node.js 22.14 이상을 사용합니다. 저장소에서 `npm ci`를 실행하고 `.env.example`을 `.env.local`로 복사합니다.

- `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`: 논담 전용 Google OAuth 웹 클라이언트.
- Google에 등록할 리디렉션 주소: 로컬은 `http://127.0.0.1:8099/api/auth/callback/google`, 운영은 `https://fplayground.com/api/auth/callback/google`.
- `NEXTAUTH_URL`: 실제 홈페이지 원점 주소. 운영은 HTTPS 필수.
- `NEXTAUTH_SECRET`: `node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"`로 생성하여 서버 환경변수로 보관합니다. 공개 저장소에 넣지 않습니다.
- `ADMIN_EMAILS`: 허용된 관리자의 Google 이메일을 쉼표로 구분합니다. 공개 회원가입은 없습니다.
- `ADMIN_GOOGLE_SUBS`: 선택한 관리자의 고정 Google 계정 ID. 지정하면 이 ID도 일치해야 합니다. Gmail/Workspace 외 이메일의 Google 계정은 이 값이 필요합니다.
- `DATA_DIR`: 저장소 **밖**의 절대 경로. Windows 예: `C:/DataAnalysis/nondam-homepage-data`. 운영에서는 영구 디스크 경로를 사용합니다. 청화당 데이터 폴더와 공유하지 않습니다.

`npm run dev`로 로컬 실행 후 `/admin`으로 접속합니다. 기존 8099 미리보기 서버가 실행 중이면 먼저 정상 종료해야 합니다. 공개 홈페이지 확인은 `/`, 영상은 `/guide.html`입니다. 다른 앱의 서버나 데이터를 종료·변경하지 않습니다.

로그인 설정이 없거나 불완전하면 방문자 페이지는 열리지만 관리자 편집 API는 열리지 않습니다. Google 로그인은 실제 OAuth 클라이언트와 허용 계정으로 마지막 확인이 필요합니다. 테스트 계정이나 인증 우회 모드는 제품 코드에 없습니다.

## 편집 방법

1. 메뉴에서 문구·FAQ·공지·정책·영상·연락처를 편집합니다.
2. **초안 저장**을 누릅니다. 저장만으로 방문자 화면이 바뀌지 않습니다.
3. **미리보기**에서 확인합니다. 관리자 로그인 없이 초안에 접근할 수 없습니다.
4. **공개 반영**을 누르면 게시됩니다. 이전 게시 내용은 게시 이력에 남습니다.
5. 복원은 이전 내용을 **초안**으로 가져옵니다. 다시 확인하고 공개 반영해야 방문자에게 적용됩니다.

공지 날짜는 한국 시간 기준이며 종료일까지 노출됩니다. 정책 본문은 일반 텍스트로 입력하며 HTML은 실행하지 않습니다. 정책의 적법성·사업자 정보·시행일은 운영자가 확정해야 합니다. 관리 기능이 법률 검토를 대신하지 않습니다.

영상 업로드는 MP4/WebM 80MB 이하, 포스터는 JPG/PNG/WebP 8MB 이하입니다. 확장자만 보지 않고 파일 시그니처를 확인하며 서버가 새 파일명을 부여합니다. 이 검사는 악성코드 검사나 모든 코덱의 재생 보장을 의미하지 않습니다. MP4는 H.264/AAC를 권장하며 업로드 후 미리보기에서 재생을 확인합니다. 자동재생하지 않습니다.

파일 주소는 자동으로 바뀌므로 캐시 판 번호를 직접 수정할 필요가 없습니다. 미게시 업로드는 관리자만 조회할 수 있습니다. 게시 이력 복원을 위해 이전 미디어는 자동 삭제하지 않습니다. 사용량은 운영자가 확인해야 합니다.

## 운영·백업

`npm run build` 후 `npm start`로 실행합니다. 기본 바인딩은 127.0.0.1:8099입니다. HTTPS 역방향 프록시 뒤에서 운영합니다. 서버리스 임시 디스크에는 이 파일 저장 방식을 배포하지 않습니다. **영구 디스크가 있는 단일 애플리케이션 인스턴스**가 전제입니다. 여러 인스턴스를 운영하려면 데이터베이스·공유 저장소로 전환해야 합니다.

`DATA_DIR/state.json`에 초안·게시본·게시 이력을 저장하고, `DATA_DIR/media`에 업로드를 저장합니다. 임시 파일 작성·동기화 후 원자적 이름 변경으로 저장합니다. 파일 잠금과 버전 비교로 동시 덮어쓰기를 차단합니다. 서버 중단으로 `write.lock`이 남으면 자동 삭제하지 않습니다. 쓰기 프로세스가 없는 것을 확인하고 운영자가 제거합니다.

정기적으로 `DATA_DIR` **전체**를 별도 저장소에 백업하고 복원 연습을 하세요. 변경 중인 파일을 피하려면 관리자 쓰기를 잠시 중단한 뒤 복사합니다. 게시 이력은 백업을 대신하지 않습니다. 배포·코드 업데이트로 이 폴더를 덮어쓰지 않습니다. 백업에는 관리자 이메일과 미게시 자료가 있으므로 비공개로 보관합니다.

관리자 삭제는 허용목록을 바꾸고 서버를 재시작합니다. 모든 관리 요청에서 허용목록을 다시 확인합니다. 세션은 최대 1시간입니다. 비상시 NEXTAUTH_SECRET을 교체·재시작하여 기존 세션을 무효화합니다. 운영 쿠키는 HTTPS에서만 사용하고 Google 계정에는 2단계 인증을 설정하세요.

## 기존 정적 파일

`site/`만 띄우면 관리자 기능은 없습니다. 영상 플레이어는 이제 빌드된 HTML에 포함돼 JS가 꺼져도 표시됩니다. `python tools/pages.py`가 config.js에서 영상 설정을 읽어 정적 페이지를 만듭니다. 관리자 서버는 게시 데이터를 기준으로 응답하므로 관리자가 저장한 내용은 Python 재생성과 무관하게 DATA_DIR에서 유지됩니다.

기존 `tools/check.py`에는 제작자의 Windows 원본 로고 경로를 확인하는 검사가 남아 있습니다. 다른 컴퓨터에서 해당 자산이 없으면 이 검사는 실행할 수 없습니다. 관리자 기능 검증은 `npm test`, `npm run build`, 영상 동작 검증은 `npm run check:video`입니다. `node tests/browser.mjs`는 별도 임시 데이터와 테스트 전용 서명 세션으로 권한·게시·업로드 및 실제 브라우저를 검사하며, 운영 Google 로그인 자체를 대신하지 않습니다. H.264/AAC 지원 Chrome 경로를 `CHROME_PATH`에 지정할 수 있습니다.

실제 공개 전: Google 실계정 로그인, 허용되지 않은 계정 거절, HTTPS, 영구 디스크 재시작 후 데이터 유지, 백업 복원, 실제 PC/휴대폰 재생을 최종 확인합니다.

## 최초 홈페이지 문구

홈페이지 문구 편집칸 위에는 최초 문구 전문과 줄바꿈이 고정 표시됩니다. `content/original-landing.json`은 관리자 기능 도입 당시 `content/initial.json`의 홈페이지 문구를 ID별로 보존한 기준 원문입니다. 초안 저장·게시·복원은 이 파일을 갱신하지 않습니다. 이후 초기 콘텐츠를 변경하더라도 이 기준 원문은 자동 재생성하거나 덮어쓰지 않습니다.
